个人网站搭建全记录

2026年8月09日14分钟阅读

  • 教程
  • 网站

本文记录本站从零搭建的完整过程。

需求

我需要一个个人网站，功能如下：

  • 用 Markdown 写内容，发布后自动渲染为 HTML
  • 按目录组织笔记（按主题分类，如电路设计、嵌入式、机械设计）
  • 支持按标签检索
  • 笔记之间能互相引用（双向链接）
  • 全文搜索
  • 数学公式渲染（电子信息的笔记大量涉及公式）
  • 代码语法高亮（C、Python、Verilog、Shell 等）
  • 构建为纯静态文件，部署到免费托管平台
  • 不依赖数据库或后端服务

我不需要：

  • 用户系统、评论系统
  • 动态内容或服务端渲染
  • 复杂的 CMS 后台

备选方案

Hugo

Go 编写的静态网站生成器。模板语法是 Go 的 html/template，主题市场有 300 多个现成主题。构建速度在所有 SSG 中最快（毫秒级）。Hugo 的内容组织依赖 frontmatter 中的 slug、categories、tags，目录结构对 URL 的影响可以通过 permalinks 配置覆盖。

不适合我的原因：模板语法较旧，双向链接需要额外配置，默认不解析 [[wikilink]] 语法。

Hexo

Node.js 生态的博客框架，中文社区活跃。主题多，插件覆盖搜索、RSS、字数统计等常见功能。hexo deploy 一条命令部署到 GitHub Pages。

不适合我的原因：本质是博客引擎，目录结构不会自动变成侧边栏导航，知识库形态需要大量手动配置。

VitePress

Vue 团队维护的文档站点生成器。默认主题左侧树形导航 + 中间正文 + 右侧大纲，内置全文搜索（Pagefind），支持 Vue 组件嵌入 Markdown。文件目录自动映射为侧边栏结构。

不适合我的原因：默认主题是文档风格，博客时间线功能弱，首页没有文章列表。适合纯文档站，不太适合博客 + 知识库混合形态。

Next.js + MDX

React 框架驱动，灵活度最高。MDX 允许在 Markdown 中直接使用 React 组件。缺点是需要写不少代码才能实现文件路由、标签系统、搜索等功能——本质上是从零搭一个 SSG。

不适合我的原因：我的专业是电子信息而非前端，投入 4-6 周学 React 才能开始写内容，不划算。

Obsidian + Quartz

Quartz 是一个专门将 Obsidian 格式的 Markdown 笔记构建为静态网站的工具。它解析 Obsidian 的 [[wikilink]] 语法并自动生成超链接和反向链接。项目由 jackyzha0 维护，MIT 协议开源。

选择它的原因：

  1. 原生支持双向链接。[[笔记路径]] 语法直接解析为 <a> 标签，同时生成反向链接数据，在页面右侧渲染”反向链接”面板。
  2. 目录即导航。content/ 下的目录结构自动生成侧边栏文件树，不需要手动配置导航。
  3. 插件链完整。内置 LaTeX（KaTeX 引擎）、语法高亮（Shiki）、RSS、站点地图、OG 图片生成、全文搜索（Flexsearch）。
  4. 零前端代码。只写 Markdown，不碰 HTML/CSS/JS。

技术架构

Quartz 的构建流程：

content/*.md          ← Markdown 源文件（你只写这个）
    ↓
[transformers]        ← 插件管线：解析 frontmatter、wikilink、Markdown → HTML
    ↓
[filters]             ← 过滤草稿等
    ↓
[emitters]            ← 输出：HTML 页面、RSS、sitemap、搜索索引、OG 图片
    ↓
public/               ← 纯静态文件（部署这个目录）

核心依赖：

包用途
remark / rehypeMarkdown → HTML 的统一生态（unified 体系）
shiki代码语法高亮
katexLaTeX 数学公式渲染
flexsearch客户端全文搜索索引
preact轻量 React 替代，渲染交互组件（搜索框、图谱、目录）
d3关系图谱（右侧栏的笔记关联图）
wsWebSocket 服务端，开发时热重载

本地预览

build 执行完整构建，--serve 启动本地 HTTP 服务器并开启 WebSocket 热重载。改完 content/ 下的文件后手动重新运行此命令。浏览器打开 http://localhost:8080。

目前 Quartz v4.5.2 没有文件监听自动重建功能，每次改完内容需要手动 rebuild。

构建输出

构建产物在 public/ 目录：

public/
  index.html                           ← 首页
  notes/网站搭建/个人网站搭建全记录.html  ← 文章页
  notes/网站搭建/                       ← 目录列表页
  tags/教程.html                        ← 标签聚合页
  index.xml                            ← RSS feed
  sitemap.xml                          ← 站点地图
  static/contentIndex.json             ← 搜索索引
  static/*.js, *.css                   ← 框架 JS/CSS
  assets/meme.jpg                      ← 用户静态资源

每个 Markdown 源文件生成一个 HTML 页面。目录生成列表页。标签生成聚合页。搜索索引是一个 JSON 文件，客户端加载后用 Flexsearch 做本地搜索。

Vercel / Netlify 方案类似，且对 Next.js 以外的框架也没有额外优势，此处略。

踩坑记录

GitHub 连接问题

直连 GitHub 有时会超时或速度极慢。可选的解决方式：

  1. 使用网络代理（代理节点选延迟低的地区）
  2. 在浏览器中下载 ZIP 包——浏览器下载通常比 git clone 快，因为它会使用多线程
  3. 若使用国内代码托管平台的镜像，注意区分同名项目（例如 Gitee 上搜到的 Quartz 有可能是同名的 Java 定时任务框架）

端口占用

第二次运行 npx quartz build --serve 时可能报 EADDRINUSE，因为上次的 Node 进程还占着端口。解决：

Linux / macOS 下对应命令为 lsof -i :8080 和 kill <PID>。

字体加载

默认配置从 Google Fonts 加载字体（quartz.config.ts 中 fontOrigin: "googleFonts"）。在部分网络环境下 Google Fonts 不可达，但字体加载失败不影响页面可用性——浏览器会回退到系统默认字体。如果介意，可以把 fontOrigin 改为 "local" 并自行提供字体文件。

内容目录变更

content/ 目录是站点的内容根目录。新建子目录后第一次构建会生成对应的列表页。目录名和文件名会原样出现在 URL 中（中文会被 URL 编码）。修改文件名或目录名会导致旧 URL 失效，目前 Quartz 不会自动生成重定向。
